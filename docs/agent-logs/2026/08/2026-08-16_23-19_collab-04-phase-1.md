## Objective

Implement the COLLAB-04 Phase 1 backend foundation without changing existing personal sync behavior: canonical user/space database keys, versioned content initialization, `_spaces.db`, and internal owner/editor membership CRUD, all with `SHARED_SPACES_ENABLED` failing closed.

## Progress

- Refactored content database access around canonical `user:<uuid>` and `space:<uuid>` keys while retaining personal compatibility wrappers.
- Added strict UUID parsing before filesystem operations and resolved-path containment assertions.
- Added versioned, fail-closed content and space-metadata initializers.
- Added internal owner/editor membership operations with no public HTTP routes.
- Migrated background revision maintenance to canonical dbKeys and made image maintenance inspect the Phase 1 no-space-images invariant rather than silently dropping space databases.
- Updated test user identities to UUIDs and ran the complete backend suite in Docker.

## Changes Made

- `backend/api-service/db.js`
  - Added `parseDbKey`, `resolveDbPath`, `getDb`, `invalidateDb`, `getHealthyDb`, and `getDbSizeBytes`.
  - Kept `getUserDb`, `invalidateUserDb`, `getHealthyUserDb`, and `getUserDbSizeBytes` as thin personal wrappers.
  - Canonicalized connection-cache keys so equal user/space UUIDs remain separate and wrapper/generic calls share one handle.
  - Added `initializeContentDb(db, kind)` with `application_schema` version 1, kind checks, legacy/unversioned upgrade behavior, user-only `backup_config`, fail-closed repair propagation, and CRR verification before recording the version.
  - Added `data/spaces/<uuid>.db` path resolution and containment.
  - Added `_spaces.db` with an ordered, transactional migration ledger and the specified `spaces`, `space_members`, `space_invites`, and `space_user_versions` tables/indexes.
  - Changed `listUserDbIds` to return sorted canonical keys for both personal and shared content DBs; retained the name for compatibility and exported `listDbKeys` as the canonical alias.
- `backend/api-service/spaces.js`
  - Added internal-only, fail-closed space creation/list/membership lookup/editor add/editor removal operations.
  - Validates auth users and UUIDs, derives owner authority from metadata rows, restricts roles to owner/editor, prevents owner removal, and increments affected users' membership versions in the same transaction.
  - No route accepts a body-supplied user identity; no public routes are mounted in Phase 1.
- `backend/api-service/revision.js` now keys maintenance locks/checkpoints and connections by canonical dbKey, covering users and spaces.
- `backend/api-service/image.js` iterates both key kinds. Because Phase 1 has no qualified space-image routes, it verifies space image tables remain empty and fails visibly if that invariant is broken; qualified space upload/prune paths remain Phase 6 work.
- `SHARED_SPACES_ENABLED` is explicitly defaulted to `false` in development and production Compose, while code enables only the exact string `true`.
- Updated backend handbook and data-model architecture documentation.
